# .xls 文件处理性能优化

## 优化日期
2024年12月（基于用户反馈）

## 问题背景
在使用 Excel 工作流工具处理 .xls 格式文件时，由于 .xls 是旧版格式，需要进行以下转换：
1. 使用 xlrd 引擎读取 .xls 文件
2. 转换为 pandas DataFrame
3. 写入临时 .xlsx 文件
4. 再使用 openpyxl 读取进行样式复制

这个过程对于大文件或重复操作会很慢，尤其是在工作流中多次使用同一个 .xls 文件时。

## 优化方案

### 1. 文件内容哈希缓存
使用 MD5 哈希值识别文件内容：
- 计算 .xls 文件的 MD5 哈希值
- 使用 `文件路径_哈希值` 作为缓存键
- 如果文件内容未改变，直接返回缓存的 .xlsx 文件

### 2. 全局缓存字典
```python
_xls_conversion_cache = {}  # 全局缓存
```
在工作流执行期间保持缓存：
- 第一次转换：完整执行转换并缓存结果
- 后续使用：直接返回缓存的 .xlsx 文件（几乎瞬间完成）

### 3. 智能清理机制
- 缓存的临时文件在 StyledSheet 清理时不会被删除
- 工作流执行完成后可选择性清理全部缓存
- 提供 `clear_xls_conversion_cache()` 函数手动清理

### 4. 性能监控
添加详细的时间统计：
```
正在转换 .xls 文件: example.xls ...
  - 读取完成 (3 个工作表, 耗时: 2.34秒)
  - 写入完成 (耗时: 1.12秒)
✓ 转换完成并缓存: example.xls (总耗时: 3.46秒)

✓ 使用缓存的转换文件: example.xls (耗时: 0.01秒)
```

## 技术细节

### 文件哈希函数
```python
def get_file_hash(file_path):
    """计算文件的MD5哈希值"""
    hash_md5 = hashlib.md5()
    with open(file_path, "rb") as f:
        for chunk in iter(lambda: f.read(4096), b""):
            hash_md5.update(chunk)
    return hash_md5.hexdigest()
```

## 注意事项

1. **缓存有效性**：
   - 缓存基于文件内容哈希，文件内容改变会自动重新转换
   - 缓存在程序运行期间有效

2. **磁盘空间**：
   - 每个缓存的 .xls 文件会在临时目录创建一个 .xlsx 副本
   - 通常临时文件不会很大（除非原文件很大）
   - 程序关闭时会自动清理

3. **并发安全**：
   - 当前实现适用于单线程工作流执行
   - 多线程环境可能需要加锁保护

## 未来优化方向

1. **持久化缓存**：
   - 将缓存保存到磁盘（如 .cache 文件夹）

2. **缓存大小限制**：
   - 限制缓存条目数量（LRU策略）
   - 限制缓存占用磁盘空间

3. **增量转换**：
   - 对于只需要部分工作表的情况，仅转换需要的部分

4. **并行转换**：
   - 对于多个不同的 .xls 文件，并行执行转换
